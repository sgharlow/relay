## 3. Shipped

### AD-1 · correctness · `a829dbe` — `npm run verify:funnel`

The runbook says the funnel "has been silently dead before… only found by driving a real browser.
**Do not trust a green suite here.**" It has happened twice. A $250 flight runs against this
instrument for four weeks, and a dead funnel reads as *zero demand* against a `< 0.5%` kill line.

| AC | Proven by |
|---|---|
| Drives a real browser, fresh context | live run, 7/7 |
| `caregiver_qualified` carries `src=qa` | read from the payload |
| `caregiver_intent` carries `src=qa`, `cta=hero` | read from the payload |
| Both events agree on `src` | asserted separately — invisible in either event alone |
| Writes nothing to the DB | the form is never submitted |
| Refuses a gate-qualifying `src` | proven with the base URL pointed at a dead port, so a broken guard still could not reach production |
| Exit non-zero on failure | planted event-name change → 3/7 fail, exit 1 |

> **My first version of this check was wrong, and it is the most useful thing in this report.** It
> asserted on the network POST — having watched that exact request minutes earlier — and reported
> *"the denominator is dead"* against a funnel that was demonstrably alive. Vercel Analytics
> suppresses automation (`navigator.webdriver`), so nothing goes over the wire; neither a headed
> browser nor a realistic UA changes it. Shipping that would have produced a check that cries wolf
> every run about the one number nobody could afford to disbelieve. It now reads `window.vaq`, the
> pre-flush queue, which observes *our trackers* — exactly what broke twice.
>
> **The claim is bounded:** a queued event proves the tracker fired. It does **not** prove Vercel
> ingested it. Delivery still needs a human reading the wire — done today, recorded below.
