### S3-5 · Re-derive the rate limiter's stance — `f53706e` · security

Taken first on both score (15, highest in the queue) and the standing security-first instruction.

`lib/http/rate-limit.ts` justified itself as the right trade *"for a $250 ad test"* and named its
upgrade trigger as lead spam during that flight. **Paid advertising was retired on 2026-08-16**, so
the trade was against a thing that no longer existed and the trigger could never fire — a
justification dead for four days that nothing noticed.

**The finding that decided the answer, and it was not about cost:** this codebase has already solved
durable metering **three times** with storage it already owns — `invite-budget.ts` (audit_log rows),
`signin-attempts.ts` (append-only + predicate), and per-code `failed_attempts`. So the choice was
never *memory or new infrastructure*; it is *memory, or the pattern already here, applied where it
is earned*. Recommendation: **Option A**, with Option C (Redis) explicitly recorded as recommended
**against** so the conventional answer is not re-proposed as the obvious one.

**⚠️ The guard failed on my own document.** `lib/ops/rate-limit-stance.test.ts` derives the endpoint
list from the code; the first draft tabulated nine public endpoints and left six authenticated ones
in prose — a document presenting itself as exhaustive, understating the guarded surface by six
routes. The second table turned out to carry the best sentence in the doc.

**Two premises in the item itself were wrong** and are corrected in place: `/api/ai/intake` and
`/api/stripe/checkout` are **authenticated**, not public.

### S3-1 · A failed renewal tells the owner — `94f56db` · correctness

`invoice.payment_failed` was not handled, and the final lapse wrote an audit entry and sent no mail.

**Nothing here changes entitlement** — `past_due` is inside `ACTIVE_STATUSES` deliberately — and the
route guard asserts the payment-failed branch never calls `upsertSubscription`, because that would
revoke access during the very window that exists to prevent it.

**Once per invoice**, deduped on the Stripe id via the audit log (no new table), because a time
window would double-send on a slow retry and suppress a genuinely new failure on a fast one.
**The record tells the truth about delivery**: check → send → record, with the outcome in the entry,
plus a distinct `NOTICE NOT DELIVERED` line.

**⚠️ Contract detail the backlog got wrong:** it required proof "against the existing webhook test
harness". There is none — that route has no test file. Logic went to `lib/` per convention, plus a
route-level guard, because every module test would stay green if the webhook stopped calling either
notifier.

### S3-2 · What a lapse does to a vault — `e7a6d37` · completeness

Established by reading every path: **a lapse changes exactly one thing — what you can ADD.** Editing,
revealing and exporting are ungated by tier; access rules and release states were never gated; the
only bulk vault deletion is in `deleteAccount()`.

**The risk closed is not a bug, it is a refactor** — somebody could move a cap onto a read path, or
add a downgrade handler that trims a vault, and nothing would notice while `/terms` promised
otherwise. Both regressions planted and red.

**🔴 A name this sprint's own backlog invented:** both E1 and E2 referred to `assertCanAddItems`,
which **does not exist** — and I had repeated it into a code comment before reading the file.
Corrected in both places.
